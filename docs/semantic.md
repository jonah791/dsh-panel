## 1 · 定位（一句话 + 负边界）

**一句话**：dsh-panel 是**前端的中转站**——把各插件**各自不同的前端**聚合到一处入口（一屏按钮/卡片），并把请求**转发**给对应插件；宿主**不规定**里面长什么样。

**它是什么**
- 一个**入口聚合器**：一屏列出所有已注册插件的入口（`title`/`icon`/`order` 来自注册表），点进去是**该插件自己的前端**。
- 一个**中转站**：托管插件的静态前端资源（`/panel-assets/<id>/…`），并把数据请求**反代**给插件自己的 handler（`/api/panel/<id>/*`）。
- 一个**契约**：`ctx.panel` 服务 + 注册契约 + 动作 ABI（Action ABI）+ **可选**的声明式视图（ViewSpec，轻量模式）。
- 一个**观测面**：实测健康 + 派发审计——这是"聚合"的价值，**不是形态锁死**。

**它不是什么（负边界，同等重要）**
- ❌ **不是渲染器**（v0.5 定位修正：主人 2026-09-22「面板插件不是让前端格式锁死，而是因为需要聚合。**各个插件前端都应该不同**。就类似**中转站**」）：宿主**不再**是"唯一渲染者"，也不要求所有插件同形。`ViewSpec` 白名单降级为**可选轻量模式**，供不想写前端的插件使用。
- ❌ 不是官方 Web GUI 的替代品：对话/会话仍是官方界面，面板只管"非对话类的可视化与操作"。
- ❌ 不是沙箱：贡献方与本宿主**同进程**，享有完整权限；见 §5 的能力诚实声明。
- ❌ 不是插件的业务逻辑：宿主不认识"磁盘清理""WQ 因子""任务板"——它只认注册契约、HTTP 转发与（可选的）视图规格/动作。
- ❌ 不是权限后门：任何触及"删数据 / 动凭据 / 动核心引擎"的动作，宿主**不得**成为绕过主体性铁律的通道（见 §5.4）。

> **定位沿革（诚实记录，含我自己的偏差）**：v0.1（2026-09-12）本节写的是「把"每个插件各写一套前端"收敛成"每个插件提交一份声明"」——那是**用统一换省事**，代价是插件的表达自由。同日主人已定调"前端可以更自由"（见 §4.6），但当时只落成 `accent` 颜色 + `density` 两个旋钮。v0.5（2026-09-22）按主人原话**改正定位**：宿主负责**聚合与中转**，前端归插件。⇒ 教训：「聚合」与「统一」是两件事——**聚合是入口的集中，统一是形态的抹平**；宿主该做前者，不该做后者。

## 2 · 术语（语义先于实现）

| 术语 | 语义 | 谁拥有 |
|---|---|---|
| **宿主（Host）** | 面板服务本体（dsh-panel）：入口聚合、静态托管、请求反代、注册表、审计、错误隔离 | 本插件 |
| **贡献（Contribution）** | 一个插件向宿主提交的一份注册声明（身份 + **前端接入** + 可选取数/动作），随该插件 apply 时注册、卸载时消失 | 消费方插件 |
| **前端接入（Frontend）** | 插件自带的前端（静态资源 + 入口页）与它自己的数据 handler（§4.7）——**形态完全由插件决定** | 消费方插件 |
| **中转（Relay）** | 宿主把 `/panel-assets/<id>/…` 映射到该插件的前端资源，把 `/api/panel/<id>/*` 转给该插件的 handler | 宿主 |
| **面板（Panel）** | 宿主首页上的**一个入口**（按钮/卡片）；点进去加载**该插件自己的前端** | 宿主呈现入口，贡献方供内容 |
| **视图规格（ViewSpec）** | 一份 JSON 可序列化的界面描述（§4.2）——**可选轻量模式**：不做前端的插件可用它让宿主代渲染 | 贡献方生成，宿主编译 |
| **动作（Action）** | 贡献方声明的可执行操作（§4.3），由宿主派发并审计；**在一屏入口上也可直接聚合为按钮** | 贡献方实现，宿主派发 |
| **宿主自检面板** | 内置面板：显示宿主自身与所有贡献的健康度（实测，不采信自报） | 宿主 |
| **消费方（Consumer）** | 任何 `inject: ['panel']` 并调用 `ctx.panel.register(...)` 的插件 | 各插件 |

> 语义纪律（v0.5 改写）：**面板是"入口"，不是"统一页面"**。宿主只保证两件事——**入口找得到**（一屏聚合）、**请求转得到**（静态托管 + 数据反代）；至于长什么样，**归插件**。⇒ 各插件前端不同是**特性**，不是需要被收敛的差异。
> （v0.1 原文写的是「面板是"声明"，不是"页面"…至于长什么样由宿主统一决定——这是主人不必学 N 种界面的原因」；该取向于 2026-09-22 被主人纠正，理由见 §1 定位沿革。）

## 3 · 概念模型

```
              ┌─────────────────────── 宿 主（dsh-panel）＝中转站 ───────────────────────┐
              │  GET /panel/        一屏入口（注册表投影：每个插件一张卡片/按钮）          │
  主人 ──────▶│  ├─ 入口聚合器（点卡片 → 加载该插件自己的前端）                          │
  (浏览器)     │  ├─ 静态托管  /panel-assets/<id>/…  → 该插件的前端资源目录                │
              │  ├─ 数据反代  /api/panel/<id>/*     → 该插件自己的 handler                │
              │  ├─ 动作派发器（Action ABI + 审计 + 破坏性二次确认；可选，见 §4.3）        │
              │  └─ 自检面板（宿主与各贡献的实测健康度）                                  │
              └───▲──────────────────────▲──────────────────────▲────────────────────┘
                  │ register(contribution)│ 静态资源 / handler    │ view()（轻量模式）
        ┌─────────┴────────┐   ┌─────────┴────────┐   ┌─────────┴────────┐
        │ 消费方插件 A      │   │ 消费方插件 B      │   │ 消费方插件 C      │ …（同进程）
        │ 自带前端（React） │   │ 自带前端（原生）  │   │ 只用 ViewSpec    │
        └──────────────────┘   └──────────────────┘   └──────────────────┘
```

**权威划分（ambiguity killer，v0.5 修正版）**
- 数据与语义权威：**消费方**（它知道自己的领域）。
- **呈现权威：消费方**（v0.5 修正）。插件决定自己前端的形态（技术栈、布局、交互）；宿主**只**决定**入口页**的样子（一屏聚合）与**中转规则**（路径映射）。
- 健康与"自述 vs 实证"权威：**宿主实测**（§4.5）——贡献方对自己的健康**没有发言权**（这一条不变）。
- 审计权威：宿主（谁在何时对哪个插件做了什么）。

## 4 · 契约

### 4.1 注册契约 `[MUST]`

- 服务名：`ctx.panel`（Cordis Service，`class PanelHost extends Service`，`super(ctx, 'panel')`）。
- 消费方声明 `export const inject = ['panel']`；宿主未挂载时**必须**保持可用（§9-7）。
- **接入方式 `[MUST]`（2026-09-12 实践补入，见 §11.5）**：消费方**必须**用 `ctx.inject(['panel'], (panelCtx) => …)` 等待宿主，**不得**用 `ctx.get('panel')` 一次性探测——加载顺序（growth-profile 在 patch L98、dsh-panel 在 L224）会让 `get` 拿到 `undefined` 且**永不重试**，表现为「插件健康但面板 404/未知面板」。
- 接口（草案签名，实现时以类型为准）：

```ts
ctx.panel.register({
  id: 'plugin-manager',        // 全局唯一，[a-z0-9-]+；重复注册 fail-loud
  title: '插件管理',
  order?: 100,                 // 导航排序（小→前）
  icon?: 'plug',               // 宿主图标白名单键，非自由 SVG
  view: async (params) => ViewSpec,          // 取数（可 async；宿主施加超时）
  actions?: Record<string, ActionSpec>,      // 见 §4.3
  description?: string,                      // 一句话用途（自检面板展示）
  style?: PanelStyle,                        // 自带视觉（v0.5）：见 §4.6
}): () => void                 // 返回 disposer；宿主内部用 ctx.effect 托管
```

- **生命周期语义**：注册即 effect——插件卸载/禁用 → 面板立刻从注册表消失（无幽灵）。宿主不持久化贡献方数据。
- **重复 id**：第二个注册 `[MUST]` 抛错（fail-loud），不得静默覆盖。理由：面板身份是合成级契约，撞车=配置错误。

### 4.2 视图规格 `[MUST]`（宿主唯一渲染对象）

- 纯 JSON 可序列化（无函数、无 DOM、无 HTML 字符串）——保证"宿主能渲染、日志能落盘、测试能快照"。
- v0.1 白名单块（**先小后扩，扩展走文档修订**）：

| block | 语义 | 关键字段 |
|---|---|---|
| `metrics` | 关键指标卡 | `items: [{label, value, hint?, tone?: ok\|warn\|bad\|muted}]` |
| `table` | 表格（可带行内动作） | `columns: [{key,label,align?}]`, `rows: object[]`, `rowActions?: actionId[]` |
| `list` | 卡片列表 | `items: [{title, subtitle?, tags?: string[], tone?}]` |
| `kv` | 键值明细 | `pairs: [{key, value}]` |
| `text` | 说明段落（纯文本，宿主负责转义） | `lines: string[]` |
| `timeline` | 事件序列 | `events: [{at, title, detail?, tone?}]` |
| `actions` | 动作按钮组 | `items: actionId[]` |
| `sections` | 容器（嵌套块） | `title?, blocks: Block[]` |

- **v0.5 表现力扩展块**（主人定调"前端可以更自由"；仍是声明式，宿主负责画法）：

| block | 语义 | 关键字段 |
|---|---|---|
| `form` | 声明式表单 → 绑定一个已声明动作（面板从"能看"变"能干活"） | `actionId`, `fields: [{name,label,type?: text\|textarea\|number\|checkbox\|select, options?, placeholder?, required?, hint?, wide?}]`, `submitLabel?`, `note?` |
| `chart` | 零依赖内联 SVG（bar / line / donut） | `chart: 'bar'\|'line'\|'donut'`, `series: [{label, value, tone?}]`, `unit?`, `height?` |
| `log` | 等宽尾部日志（严重度着色） | `lines: [{at?, level?: info\|ok\|warn\|error\|debug, text}]` |
| `progress` | 量表条（值夹到 [0,max]） | `items: [{label, value, max?, tone?, hint?}]` |
| `tabs` | 客户端分页容器（嵌套块） | `items: [{label, badge?, blocks: Block[]}]` |

- `[MUST]` **形状校验**：宿主在 `view()` 出口跑 `validateViewSpec`（已知 kind 的必备数组字段、`chart` 取值、`form.actionId`、块数 ≤ 2000、嵌套 ≤ 8 层）；不合规**响亮降级**而不是渲染成空块。未知 kind 放行（渲染器降级为"未知块"提示，白名单先小后扩）。
- `[SHOULD]` 每个块带可选 `title`；空数据渲染为空态文案，不渲染空白区域。
- `[MUST]` 表单提交与按钮走**同一条**派发路径（分级/审批门/确认门完全一致）；表单缺少动作元信息时保守按 `write` 处理。
- `[MUST]` 宿主对所有字符串做 HTML 转义；**ViewSpec 里出现原始 HTML 一律当文本**。

### 4.3 动作 ABI `[MUST]`

```ts
type ActionSpec = {
  label: string
  level: 'read' | 'write' | 'destructive'
  params?: Record<string, 'string' | 'number' | 'boolean'>   // 宿主据此生成最小表单
  run: (params, ctx: { sessionId?: string; now: string }) => Promise<{
    ok: boolean
    data?: unknown      // 必须是可序列化；宿主渲染为 JSON 文本块
    message?: string    // 面向主人的一句结果说明
  }>
}
```

- 派发：`POST /api/panel/action` body `{panelId, actionId, params, confirm?}`。
- `[MUST]` 未知 `panelId`/`actionId` → 400/404，**零副作用**，写审计。
- `[MUST]` `level: 'destructive'` 且 `confirm !== true` → 拒绝执行 + 审计（`denied`）。
- `[MUST]` 每次派发写审计：`DSH_HOME/panel/audit.jsonl`，字段 `{at, panelId, actionId, level, paramsDigest, outcome, durationMs, message}`——`paramsDigest` 存哈希不存原值（凭据不落盘纪律）。
- `[SHOULD]` 动作执行超时（默认 10s）→ 返回 `ok:false, message:'超时'`，副作用由贡献方自行负责幂等。

### 4.4 HTTP 面 `[MUST]`

| 方法 | 路径 | 语义 |
|---|---|---|
| GET | `/panel/` | 外壳 HTML（独立资源文件；`cache-control: no-store`） |
| GET | `/panel/assets/*` | 宿主**自身**的静态资源（prefix 路由，白名单目录，禁路径穿越） |
| **GET** | **`/panel-assets/<id>/…`** | **v0.5 新增**：该插件自己的前端静态资源（`frontend.assetsDir`）；**按插件根**做穿越校验；未声明 `frontend` → 404 |
| **任意** | **`/api/panel/<id>/*`** | **v0.5 新增**：反代给该插件的 `handle`；未声明 `handle` → **404，不回落不猜测** |
| GET | `/api/panel/registry` | 注册表投影：`[{id,title,order,icon,description,health,(frontend?)}]`（**不含** ViewSpec） |
| GET | `/api/panel/view?id=` | `{ok, spec, generatedAt, durationMs, degraded?}`（**轻量模式**用） |
| POST | `/api/panel/action` | §4.3 派发 |
| GET | `/api/panel/selfcheck` | 宿主自检：贡献健康实测 + 宿主版本 + 计时统计 |

- `[MUST]` 全部 JSON 响应统一信封 `{ok: boolean, ...}`；错误含 `error` 字段（字符串）。
- `[待逼近]` 实时性：v0.1 = 轮询（面板可见时 5s，不可见时停）+ 手动刷新；SSE 见 §10-Q4。

### 4.5 失效与降级语义 `[MUST]`（本次事故的纪律下沉）

- **单面板故障隔离**：`view()` 抛错 → 该面板渲染降级态（显示错误原文 + 重试按钮），**其余面板与外壳不受影响**。
- **超时**：`view()` 超过 `viewTimeoutMs`（默认 2000ms）→ 该面板标记 `超时`，宿主返回 `degraded: true` 而不是一直转圈。
- **实测健康，不采信自报**：宿主记录每次 `view()` 的 `ok/durationMs`，据最近 N 次得出 `health: ok|degraded|down`。**贡献方声明的状态文字不得作为健康依据**（§5.0 的纪律：机制自述 ≠ 实证；见 AGENTS.md §5.17）。
- **宿主缺位**：`ctx.panel` 不存在时，消费方 `[MUST]` 降级（记录日志/继续原有行为），不得抛错、不得阻塞自身主功能。
- **宿主自身不可用**：面板页 404/500 时，主人仍可用 Telegram 与对话通道——面板是**增强**，不是命脉。

### 4.6 皮肤层与自带视觉 `[MUST]`（v0.5 · 主人 2026-09-13 定调"前端可以更自由"）

面板是**独立页**（§6 主通道），不受官方 Web 皮肤约束；自由度收敛为两条声明式规则，而不是开放任意 CSS：

1. **皮肤（外壳级）**：外壳所有颜色/圆角/字体/间距过设计令牌（`--bg/--fg/--card/--border/--topbar/--nav-bg/--sunken/--btn/--accent/--ok/--warn/--bad/--muted/--radius/--font-ui/--font-mono/…`），换主题只换令牌、不动结构。内置三套：
   - `ink`（墨青，默认）：冷灰深色，通用；
   - `terminal`（终端）：近黑 + 等宽 + 零圆角，为日志/仪表型面板；
   - `paper`（纸质）：浅色阅读型，为文档/档案/长表格。
   解析优先级 `[MUST]`：**URL `?theme=` > 本机记忆（localStorage）> 默认 `ink`**（URL 优先是为了链接可分可复现）。
2. **面板自带视觉（贡献级）**：`style?: { accent?: string; density?: 'comfortable' | 'compact' }`。
   - `accent` **只接受颜色字面量** `#rgb` / `#rrggbb` / `#rrggbbaa`——CSS 注入面收敛为一个色值（不接受选择器/函数/`var()`）；非法值**注册时 fail-loud**（不静默丢弃：否则面板以为换了色，实际没有）。
   - `density: 'compact'` 落到容器 `data-density`，紧凑面板自报信息密度。
   - 宿主渲染层**再验一次**形状（渲染层不信任输入），与注册时校验是两道闸而非重复。
3. **刷新纪律 `[MUST]`**：自动刷新重建面板 DOM，**不得带走用户正在做的事**——标签页选择按 `(panelId|tabs|标签集合)` 记忆并恢复；表单草稿按 `(panelId|actionId)` 记录 / 回填 / 提交成功才丢弃；焦点在面板内输入控件上时，本轮自动刷新跳过（让位给用户）。

### 4.7 前端接入契约 `[MUST]`（v0.5 新增 · 主人 2026-09-22 定调「各个插件前端都应该不同…就类似中转站」）

**语义**：插件的**前端形态归插件**。宿主不规定技术栈、不规定布局、**不解析其 HTML**——宿主只做三件事：**给入口、托管资源、转发请求**。

**注册面（草案签名，实现时以类型为准）**：

```ts
ctx.panel.register({
  id: 'dream-tavern',
  title: '梦境酒馆',
  order: 35,
  icon: '🎭',                        // v0.5：允许自由字符串（含 emoji）；宿主只做文本转义
  description: '人物卡文字游戏 + 上下文装配单逐字节可验',
  frontend: {                        // ← 本版新增（可选块）
    assetsDir: 'web',                // 相对插件根目录；缺省 = 无静态资源
    entry: 'index.html',             // 挂载入口（相对 assetsDir）
  },
  handle: async (req) => ({ status: 200, body }),   // 插件自己的数据接口（可选；草案，实现时定形）
  actions: { /* §4.3 动作 ABI，可选 */ },
  view: async () => ViewSpec,        // §4.2 轻量模式，可选
}): () => void
```

**三条 `[MUST]`**
1. **入口聚合**：宿主首页 = **一屏**列出所有贡献（卡片/按钮，按 `order` 排）。**不得**做「左侧多页导航 + 点一项切一页」——那正是 v0.4 被主人否掉的形态。
2. **资源隔离**：`GET /panel-assets/<id>/…` 只映射到**该插件自己**的 `assetsDir`；跨插件路径穿越**必须**拒绝（前缀校验要按**插件根**做，不只是按宿主根）。
3. **反代隔离**：`/api/panel/<id>/*` 只交给**该插件**的 `handle`；未声明 `handle` 的插件在该前缀下返回 404（**不回落、不猜测**）。

**降级与兼容（不得破既有插件）**
- 只给 `view()` ⇒ **轻量模式**：宿主代渲染，§4.2 白名单块**继续有效**（为向后兼容而保留）。
- 只给 `frontend` ⇒ **全托管模式**：宿主不碰其内部，只托管 + 转发。
- 两者都给 ⇒ 入口页显示卡片，点进去加载 `frontend.entry`；`view()` 仅用于宿主做聚合摘要（可选调用）。
- 都没给 ⇒ 注册时 **fail-loud**（一个没有任何呈现方式的贡献是无意义的）。

**安全（承 §5.0 能力诚实声明）**
- 托管插件静态资源 + 反代其 handler ⇒ **能力 ≠ 沙箱**：贡献方与宿主同进程、同权限。
- `/panel-assets/*` 与 `/api/panel/<id>/*` **仅监听回环**（§5.1），本版不扩大暴露面。
- 宿主**不解析、不注入、不重写**插件前端内容——只做路径映射与转发。**"前端自由"必须是真的**：一旦宿主开始改插件页面，这条契约就名存实亡。

## 5 · 信任与安全边界

### 5.0 能力诚实声明（能力 ≠ 沙箱）
面板宿主提供的是**便利与一致性**，不是隔离。贡献方与本插件同进程运行，拥有与我相同的权限——这在自研插件生态里是可接受的（都是"我"），但**必须写在 README 与文档里**，不得宣传为安全边界。

### 5.1 网络面 `[MUST]`
- 仅监听回环（`host=127.0.0.1`）；页面与 API 同源，认证由宿主 cookie 承担；`/api/*` 不额外造 token 体系（同源信任模型，沿用 `dsh-panel-plugin` 技能既有结论）。
- `[MUST]` 路径穿越防护（assets 白名单 + `resolve` 前缀校验，参照官方 `frontend-static` 的 `sep` 用法，Windows 反斜杠是已知坑）。
- `[待定]` 公网暴露（`0.0.0.0`）时面板必须强制关闭或加独立认证——默认不提供。

### 5.2 破坏性动作 `[MUST]`
- 三层分级（`read/write/destructive`）+ 二次确认 + 审计。
- 不可逆操作（删除数据、卸载带数据的插件）**默认不提供面板入口**；确需时必须走 §5.4。

### 5.3 输入 `[MUST]`
- 全部动作参数经类型 + 白名单校验（`params` schema 由贡献方声明，宿主校验后才调用 `run`）。
- `paramsDigest` 落盘用哈希；原值不入审计日志。

### 5.4 与主体性铁律的关系 `[MUST]`
面板**不得**成为绕过 AGENTS.md「须请示三类（删数据 / 动凭据 / 动核心引擎）」的后门：
- 这类动作在宿主侧**拒绝派发**，改为产出"请示项"（写任务板/Telegram 提请），由我在正常通道拿到授权后再执行。
- 判据（可测试）：注入一个 `destructive` 且触及"删数据"的动作 → 宿主返回 `denied` + 审计 `reason='requires-approval'`，且**未调用** `run`。

## 6 · 与官方 Web GUI 的关系（三条通道的取舍）

| 通道 | 机制 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| **独立页** | `webServer.register('/panel/')` + 自包含 HTML | 零官方 client 依赖；官方升级不易碎 | 与对话界面分离，需要单独切换/开标签 | **主通道** |
| **官方 index 注入** | `webserver/index-inject` 结构化行（`global/script/script-src/style/html`） | 可在官方页面加入口/徽标/样式，主人不必记 URL | 依赖官方 DOM/样式约定，有升级耦合 | `[待定]`：M3 评估，先做"轻量导航入口"而不是深度嵌 UI |
| **官方 client slot / Conversation Node** | 官方 client bundle（08-16 成长档案 tab 先例） | 与对话同屏，体验最佳 | bundle + 版本对齐成本（09-11 审计已量化） | **原则上不采用**——**唯一例外见 §6.1**（本插件自己的入口按钮） |

### 6.1 唯一例外：面板入口按钮（2026-09-13 主人定调）

主人定调：**GUI 只留 1 个入口——打开面板宿主 `/panel/`；其余自研前端全部改成面板宿主里的一页**。据此：

- 本插件**自己**提供 `./client`（`src/client/index.tsx`），只注册**一个** `conversation.session.header.actions` 贡献：`id=panel`、`order=20`、`label=面板`，点击 `window.open('/panel/', '_blank', 'noopener')`。
- **例外为什么可以被接受**（对照 §6 的代价）：本 bundle 不做任何 RPC（不需要 `remote`/`$mount`）、不注册 Conversation Node、不做 CSS Modules——对官方客户端的依赖面收敛为「槽位名 + 一个按钮」，是 §6 所列三种代价里最小的形态。
- **纪律**：此例外**只属于本插件**。其余插件**不得**再注册任何官方 GUI 槽位（含 `conversation.session.header.actions` / `conversation.view` / `shell.overlay` / `conversation.chat.*`）；需要界面就交面板贡献（§4.1）。
- **产物协议**（实现事实，勿与源码混淆）：Web 客户端模块系统加载的是 `lib/client.js` 的**字节**，它必须自行调用 `window.__ModuleLoader__.load({ id: <包名>, factory })`，且 `exports` 必须有 `apply`（缺失会白屏）。构建链（v0.4 起**零额外依赖**）：`tsc -p tsconfig.client.build.json`（CJS → `lib/.client-build/`）→ `scripts/bundle-client.mjs`（拼模块注册表 + 包装）→ `lib/client.js`（`npm run bundle`）。只用到本仓已装的 `typescript`；JSX 类型由本地垫片 `src/client/jsx-shim.d.ts` 回答（本仓无 `react` / `@types/react`，而 live 插件目录跑 `pnpm install` 会触发 web 重启——见 AGENTS.md §5.15 §7）。注意 `build` 只跑 host 侧 `tsc`（tsconfig `exclude: ["src/client"]`），**改客户端源码必须另跑 `npm run bundle`**，否则线上仍跑旧产物；`npm run typecheck` 两条 tsconfig 都查。

## 7 · 非功能约束 `[MUST]`

1. 零 `@deepseek-ai/dsh-client-*` 依赖（构建产物可 grep 断言）。
2. HTML/JS 资源放**独立文件**（`src/assets/*` → 构建拷 `lib/assets/`），**永不写进 TS 模板字符串**（`dsh-panel-plugin` 技能铁律，历史踩坑）。
3. 不引重型前端依赖（无框架、无 CDN、无外部字体、无外部 URL）；**外壳体积有界且如实记录**——硬预算 **120KB**，超限必须先改这一行并写明理由，**不许悄悄超**；当前实测 **96,979 字节**（v0.5，见 §9-9）。
   *沿革（诚实记录）*：本条原写「外壳 ≤ 60KB」，但 v0.4.0 加厚皮肤层与表现力块族后已达 **79,729 字节**，而 §9-9 仍在状态列打 ✅ ——**预算与实际脱节且无人察觉，等于该预算从未生效**。教训：约束必须配一条**会亮的判据**（这里是 §9-9 的体积实测），否则它只是文字；这也正是 §5.9 规则 2「防线必须有尸体测试」在文档层的形态。
4. 无外部网络请求（面板永不访问公网）。
5. `view()` 取数应为只读快照；写操作一律走 `actions`。
6. 命名遵循官方 `plugin-write` 规范（`dsh-plugin.naming.json` 各 surface 名一致，routes 不以 `/` 结尾）。

- **被实践暴露（三条仅真浏览器可见的缺陷，自写 DOM 桩全绿也测不出）**：
  1. **icon 语义名被当文本渲染**：`panel.icon` 是 `plug`/`history`/`users` 这类**语义名**（旧版导航**从未渲染过它**，grep 可证），卡片直接当文字显示 ⇒ 在 24px 容器 + 20px 字号下逐字竖排成 `p`/`l`/`u`/`g`。⇒ 改为字母徽标（非 ASCII 取一字符、ASCII 短符号原样、语义名取首字母），面包屑同步复用。
  2. **iframe 卡在浏览器默认 150px**：`.frame-wrap`/`.frame` 上的 `flex:1` 全部落空——真正需要撑满的是 **`.panel-body`**（`content` 的直接子项），而它**没有任何样式定义**（默认 `flex:0 1 auto` ⇒ 高度由内容决定，未定高的 iframe 即 150px 默认值）。实测定位链 `content 753 / panel-body 150 / iframe 150` ⇒ 补 `.content.frame-mode .panel-body{flex:1; min-height:0; display:flex; flex-direction:column}` 后 iframe 150 → **683px**。
  3. **整屏「未知」噪音**：新版首页不再自动为每个面板调 `view()` ⇒ 实测健康恒为 `unknown`，而卡片与面包屑都按异常显示。⇒ `unknown` 与 `ok` 一致不缀（`degraded`/`down` 才需要一眼看见）。
  ⇒ **教训**：同伴的自写 DOM 桩（33/33 全绿）覆盖了行为逻辑，却**不含布局**——凡「尺寸 / 对齐 / 占满」类判据，桩恒绿而真浏览器恒红。这是 §11.8「界面必须真的看一眼」的第二次实证。
- **被免疫层两次正确拦截（是防线在工作，不是故障）**：① 首次 `daemon_restart` 被守护预检拦下：`src/frontend.ts` 比 lib 新（同伴正在改代码）⇒ 若放行就会拿旧产物重启；② 第二次被拦：预检时刻早于最新构建 2 秒 ⇒ 判「该预检未验证当前组合」。两次都**未造成错误上线**；也说明「重启失败」要**读预检理由**，不能当随机故障重试。
- **被实践修正（我的验收脚本两次假绿——问题在判据，不在产品）**：
  1. 按裸数组解析 `/api/panel/registry` ⇒ `panels.find is not a function`（真形状是信封 `{ok,host,panels}`）；
  2. 拿 `host.version` 当「新代码已加载」判据 ⇒ `VERSION` 常量未随 `package.json`(0.4.1) 更新，把**已完成的重启**误报为失败 ⇒ 改用行为判据（新路由能否服务**合法**请求）；
  3. 另有一次 `node … | tail; echo $?` 取到的是 `tail` 的退出码、**恒为 0** ⇒ 那个「通过」无分辨力（与 §5.9 规则 2 同型，当场自踩）。
- **未实现 / 边界（如实）**：§4.7 降级矩阵的「view/frontend/handle 三者都没给 ⇒ 注册 fail-loud」；`web/` 不在 `package.json` 的 `files` 白名单与 copy-assets 范围（本地可用，**打包/发布会丢**）；`VERSION` 常量与包版本不一致；`readBody()` 超 1MB 时 promise 不结算（请求悬挂）。后三条为既有缺陷，本轮仅列出未修。

## 11.6 · 与实现的关系

- **主实现**（本文档描述的唯一真源）：`src/index.ts`（插件装配 + webServer 注册）、`src/host.ts`（`PanelHost` Service：注册表/路由/超时/审计）、`src/registry.ts`（注册与 ViewSpec 校验 + `decideDispatch` 判定）、`src/types.ts`（契约类型）、`src/audit.ts`（`audit.jsonl` + paramsDigest）、`src/assets/shell.html`（自包含外壳，零官方 client 依赖）、`src/panels/*.ts`（五个内置面板：plugin-manager / taskboard / growth-profile / agent-teams / audit）、`src/client/index.tsx` + `src/client/jsx-shim.d.ts`（唯一 GUI 入口按钮 + 零依赖 JSX 类型垫片）、`scripts/bundle-client.mjs`（客户端产物协议打包）。
- **消费方实现**（非副本，各自独立）：`self-plugins/dsh-growth-profile/src/panel.ts`（首个消费方；不 import 宿主类型，用本地结构类型 + `ctx.inject(['panel'])` 接入）。
- **同语义副本**：无——本能力单实现单仓库；跨插件协作走**契约**（§4.1/§4.2/§4.3）而非复制源码。
- **未实现 / 未验证（显式标注）**：M3 的官方 `index-inject` 导航入口（未做，见 §6）；SSE 实时推送（v0.1 走轮询，见 U）；`ctx.panel` 的对外发布与命名规范（未做）。
- **系统注册**：本文档登记于语义文档系统 `docs/semantics/registry.json`（id=`panel-host`），drift 检查（D1–D6）覆盖本文件。
